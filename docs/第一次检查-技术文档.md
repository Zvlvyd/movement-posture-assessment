```
┌──────────────────────┴───────────────────────────────┐
│                   后端 (Python 3.10+)                   │
│  FastAPI + Uvicorn + SQLAlchemy ORM + Pydantic v2     │
│  PyJWT + httpx + OpenCV + NumPy                       │
└──────────────────────┬───────────────────────────────┘
                       │
┌──────────────────────┴───────────────────────────────┐
│              AI 推理层 (Ultralytics + DeepSeek)        │
│  YOLOv8s-Pose (关键点检测) + DeepSeek-v4-pro (报告)    │
└──────────────────────┬───────────────────────────────┘
                       │
┌──────────────────────┴───────────────────────────────┐
│                   数据库 (MySQL 8.0)                    │
│  13 张业务表 + SQLAlchemy ORM + 连接池                 │
└──────────────────────────────────────────────────────┘
```

### 2.2 选型理由

| 技术 | 选择理由 |
|------|----------|
| **FastAPI** | 原生异步支持、自动 OpenAPI 文档、WebSocket 一等公民、Pydantic 类型校验 |
| **React 18 + TypeScript** | 类型安全、生态丰富、Ant Design 企业级 UI 组件库 |
| **Vite 5** | 极速 HMR、原生 ESM、比 Webpack 快 10x+ |
| **MySQL 8.0** | 关系型数据、事务支持、连接池稳定；兼容 SQLite 开发模式 |
| **YOLOv8s-Pose** | 实时推理（30+ FPS）、COCO 17 关键点、Ultralytics 易用 API |
| **WebSocket** | 逐帧双向通信（摄像头帧上传 → 骨骼 + 评分回传）、低延迟 |
| **FSM 状态机** | 动作阶段识别（准备→向心→等长→离心→完成）、可解释性强 |
| **DeepSeek-v4-pro** | 中文医疗/运动康复领域能力强、API 兼容 OpenAI 格式、成本可控 |
| **Zustand** | 轻量状态管理（<1KB）、无 boilerplate、比 Redux 简洁 |
| **Ant Design 5** | 中文友好、组件丰富（Table/Form/Modal/Progress）、主题定制 |

## 3. 系统架构

### 3.1 分层架构

```
┌──────────────────────────────────────────┐
│  Routers (路由层)                          │
│  - 参数校验 (Pydantic)                     │
│  - 权限控制 (JWT + 角色依赖注入)            │
│  - HTTP 端点 + WebSocket 端点              │
├──────────────────────────────────────────┤
│  Services (业务逻辑层)                      │
│  - 编排算法模型                             │
│  - 管理 WebSocket 会话生命周期              │
│  - 数据持久化                               │
├──────────────────────────────────────────┤
│  Models (算法模型层，纯 Python)              │
│  - YOLO-Pose 推理引擎                      │
│  - 角度计算 + 评分引擎                      │
│  - FSM 动作识别状态机                       │
│  - 多证据融合引擎                           │
├──────────────────────────────────────────┤
│  Database (数据持久层)                      │
│  - SQLAlchemy ORM                         │
│  - 连接池 (pool_size=10, max_overflow=20) │
└──────────────────────────────────────────┘
```

### 3.2 实时数据流

```
摄像头 → get_user_media() → canvas 捕获
  → WebSocket.send(JPEG base64)
    → BaseWebSocketHandler.decode_frame()
      → YOLO-Pose 推理 → COCO 17 关键点
        → AngleCalculator.compute() → 关节角度
          → FSM 状态机 / 评分引擎
            → WebSocket.send(JSON)
              → SkeletonOverlay 渲染骨骼
              → 实时反馈 / 评分面板更新
```

### 3.3 关键设计模式

| 模式 | 应用场景 | 实现 |
|------|----------|------|
| **单例模式** | YOLO 模型全局复用 | `ModelManager` 双检锁线程安全 |
| **模板方法** | WebSocket 处理基类 | `BaseWebSocketHandler` 提供帧解码/角度计算 |
| **策略模式** | 双模式评分 | `DualModeScorer` basic/advanced 切换 |
| **状态机模式** | 动作阶段识别 | 7 个独立 FSM 状态机 |
| **观察者模式** | WebSocket 实时推送 | FastAPI WebSocket 异步迭代 |
| **工厂模式** | FastAPI 应用创建 | `create_app()` 统一注册路由/中间件 |

- `compute_angles()` — 关键点 → 10 个关节角度
- 统一的帧率控制、错误处理、会话清理

## 10. 分工说明

### 10.1 四层分工架构

根据概要设计文档，系统按四层架构分为四个角色：

```
┌──────────────────────────────────────────────┐
│  Person D — 前端应用层                         │
│  React + TypeScript + Vite + Ant Design       │
│  页面组件 / 路由 / 状态管理 / WebSocket 客户端  │
├──────────────────────────────────────────────┤
│  Person C — 后端 API 层                        │
│  FastAPI + Pydantic + SQLAlchemy              │
│  路由 / 参数校验 / 权限 / 数据库 CRUD          │
├──────────────────────────────────────────────┤
│  Person B — 业务引擎层                         │
│  WebSocket Handler / 评分引擎 / FSM / 多证据融合│
│  处方推荐 / 报告生成 / 学习对比                 │
├──────────────────────────────────────────────┤
│  Person A — 模型推理层                         │
│  YOLO-Pose 封装 / 角度计算 / 姿势分析           │
│  关键点后处理 / 骨架可视化                      │
└──────────────────────────────────────────────┘
```

### 10.2 各层交付物

| 角色 | 主要交付物 | 文件数 |
|------|-----------|--------|
| **Person A** (模型推理层) | `engine.py`, `yolo_pose_engine.py`, `angle_calculator.py`, `posture_analyzer.py`, `pose_postprocessor.py`, 知识库 JSON | ~10 |
| **Person B** (业务引擎层) | `scoring.py`, `fms/` 子系统, `assessment/` 子系统, `action_recognizer/` FSM, `prescription/` 推荐引擎, 所有 WebSocket Handler | ~25 |
| **Person C** (后端 API 层) | 11 个 Router, 2 个 Schema 文件, `auth_service.py`, `prescription_service.py`, `report_service.py`, 数据库 Models, Seed | ~18 |
| **Person D** (前端应用层) | 18 个 Page, 4 个 Component, 1 个 API Service, 1 个 Store, 1 个 Hook, Types, 工具函数 | ~28 |

### 10.3 模块交互关系

```
Person A (模型推理)
    ↑ 调用
Person B (业务引擎) ──→ Person C (后端 API)
                              ↑ HTTP/WS
                        Person D (前端应用)
```

- Person B 依赖 Person A 的 YOLO 模型推理和角度计算能力
- Person C 调用 Person B 的业务服务完成请求处理
- Person D 通过 HTTP REST 和 WebSocket 与 Person C 通信
